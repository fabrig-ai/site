Agents write it. Code lands it.

fabrig is a reliable, scalable and flexible agent-based software factory. Agents write and repair the code, but never hold the merge: landing is deterministic procedure, pinned to an exact commit.

The landing guarantee

Mechanics are code.
Judgement is an LLM’s.

A model is woken only to produce a change, repair it, review it or resolve a conflict. Queueing, updating and merging are deterministic procedure, and authority enforces the split.

  1. produce

    An agent is woken to write the change, under a charter and a budget.

  2. gate

    Procedure runs the checks. Receipts are keyed by the tree: what is proved stays proved.

  3. repair

    Red? An agent is woken to fix what the gate named, and the gate runs again.

  4. resolve

    A conflict on update? An agent is woken for that alone. Updating itself stays code.

  5. exact-commit merge

    Pinned to the commit the gate proved. Landing rules are checked here, whatever a task’s authority says.

Reliable

Effects are made once.

Each kind of write has a recovery class. An uncertain one that can’t be recovered waits for a person instead of guessing.

Underneath
  • Recovery classes: keyed, conditional, idempotent, unrecoverable.
  • Effects go through an outbox, released only after their commit is durable.
  • Retry deadlines are absolute and committed before each attempt.
  • Fencing uses ordered grace periods.
  • Restart follows a fixed script, ending with the outbox settled by key before any new decision.
  • Temporal, Inngest and LangGraph give you at-least-once activities and leave idempotency to you.

Scalable

A tree is proved once.

Gate receipts are reused by every landing and worker, so the queue spends its runs on what changed. Workers scale out across hosts.

Underneath
  • The target: a ready branch lands first time, within minutes, and no branch waits for another’s fault.
  • Merging is pinned to an exact commit, so main’s commit is the gated one.
  • Verification after landing uses bisection to assign blame.
  • High availability is planned, on a distributed, replicated single-writer KV store (skein-kv).

Flexible

Five primitives, any workflow.

Task, executor, message, authority, connector. jig builds plans, chats and reviews from them, as flexible as a coding agent at a terminal.

Underneath
  • An executor is an agent, a procedure or a person.
  • Delegated authority only narrows.
  • Budgets are carved from the parent’s.
  • Work outlives processes and machines.
